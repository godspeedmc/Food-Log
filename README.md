# Food Log

Food Log is a mobile-friendly restaurant tracker for saving places from Instagram and OpenRice, organizing anniversary options, recording visits and ratings, and viewing logged restaurants by Hong Kong district.

The current version stores restaurant records in **Supabase** and includes JSON **Export** and **Import** backup functions.

## Features

- Main restaurant shortlist
- Anniversary restaurant planner
- Add, edit, and delete restaurant records
- Visited / not visited tracking
- Good / Okay / Skip ratings
- Anniversary statuses: Candidate, Shortlisted, Booked, and Visited
- Instagram and OpenRice links
- Price ranges
- Search and filters
- Hong Kong district map summary
- Supabase cloud database storage
- JSON backup export
- JSON backup import with Replace or Merge options
- Mobile-friendly Progressive Web App layout

## Supabase Setup

### 1. Create the database table

In the Supabase dashboard, open **SQL Editor**, create a new query, and run:

```sql
create table if not exists public.restaurants (
  id bigint generated by default as identity primary key,
  category text not null default 'main'
    check (category in ('main', 'anniversary')),
  name text not null,
  area text default '',
  cuisine text default '',
  address text default '',
  phone text default '',
  note text default '',
  budget text default 'Below $50',
  instagram_url text default '',
  openrice_url text default '',
  visited boolean not null default false,
  rating text default '',
  status text default 'Candidate',
  created_at timestamptz not null default now()
);

alter table public.restaurants enable row level security;

grant select, insert, update, delete
on table public.restaurants
  to anon;

drop policy if exists "food_log_select" on public.restaurants;
drop policy if exists "food_log_insert" on public.restaurants;
drop policy if exists "food_log_update" on public.restaurants;
drop policy if exists "food_log_delete" on public.restaurants;

create policy "food_log_select"
on public.restaurants
for select
to anon
using (true);

create policy "food_log_insert"
on public.restaurants
for insert
to anon
with check (true);

create policy "food_log_update"
on public.restaurants
for update
to anon
using (true)
with check (true);

create policy "food_log_delete"
on public.restaurants
for delete
to anon
using (true);
```

### 2. Configure the frontend

In `index.html`, set the Supabase project URL and anon/public key:

```javascript
const SUPABASE_URL = 'YOUR_SUPABASE_PROJECT_URL';
const SUPABASE_ANON_KEY = 'YOUR_SUPABASE_ANON_KEY';

const db = window.supabase.createClient(
  SUPABASE_URL,
  SUPABASE_ANON_KEY
);
```

Use only the anon/public key in the browser. Never place a Supabase database password or `service_role` key in the repository.

## Database Behaviour

The Supabase-connected application writes changes directly to the `public.restaurants` table:

- Adding a restaurant inserts a new row.
- Editing a restaurant updates the matching row by database ID.
- Deleting a restaurant removes the matching row.
- Changing visited status updates `visited`.
- Selecting Good, Okay, or Skip updates `rating`.
- Changing an anniversary status updates `status`.

After a successful change, the app reloads the latest records from Supabase.

## Backup and Restore

### Export

Select **Export** in the app header to download a JSON backup containing both Main and Anniversary records.

Example filename:

```text
food-log-supabase-backup-2026-08-25.json
```

### Import

Select **Import** and choose a Food Log JSON backup.

- Select **OK** to replace all existing Supabase restaurant records with the backup.
- Select **Cancel** to merge the backup and add records that are not already detected in Supabase.

Export a backup before using Replace or performing a large deletion.

## Publish with GitHub Pages

### 1. Create the repository

Create a public GitHub repository named `food-log`.

### 2. Upload the files

Upload all project files to the repository root. Confirm that the latest application file is named `index.html`.

### 3. Enable GitHub Pages

In the repository:

1. Open **Settings**.
2. Select **Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**.
4. Select the `main` branch.
5. Select `/ (root)` as the folder.
6. Save the settings.

GitHub will show the published site address in the Pages settings after deployment.

### 4. Install on Android

1. Open the published GitHub Pages site in Chrome.
2. Open the Chrome menu.
3. Select **Install app** or **Add to Home screen**.
4. Launch Food Log from the home-screen icon.

Hosting the app avoids Android's temporary `content://` file address and the `ERR_FILE_NOT_FOUND` problem that can occur when reopening a local HTML file.

## Updating the App

When publishing a new version:

1. Replace the relevant files in the GitHub repository.
2. Keep the main page named `index.html`.
3. Increase the cache name in `service-worker.js`, for example:

```javascript
const C = 'food-log-v16';
```

4. Commit the changes.
5. Reopen or refresh the installed app.

Changing the cache name helps the service worker switch to updated application files.

## Security Notes

The current setup permits anonymous select, insert, update, and delete operations through Supabase Row Level Security policies. This is convenient for a personal prototype, but anyone with access to the hosted app may be able to use the same permitted operations.

For stronger protection, add Supabase Authentication, a `user_id` column, and policies that restrict each record to the signed-in account.

Do not commit any of the following:

- Supabase database password
- `service_role` key
- PostgreSQL connection password
- Private credentials or secrets

## Troubleshooting

### `Could not find the table public.restaurants`

Run the SQL in the **Supabase Setup** section and confirm that `restaurants` appears in **Table Editor**.

### Changes do not save

Check that:

- The Supabase project URL is correct.
- The anon/public key belongs to the same project.
- The table exists.
- RLS is enabled.
- The required policies and grants exist.
- The device has an internet connection.

### The old version still appears

Increase the cache version in `service-worker.js`, commit the update, and refresh or reopen the installed app.

### A restaurant was deleted accidentally

Use **Import** with a previously exported JSON backup. Choose Replace only when the backup should overwrite all current records; otherwise choose Merge.
